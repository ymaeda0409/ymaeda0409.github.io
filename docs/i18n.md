# Internationalization (i18n) Architecture

本システムは **最初から多言語前提**。英語・Chichewa・日本語に依存した `if` 文は一切書かず、
**Locale をキーとした共通の翻訳解決** だけで表示を切り替える。

---

## 1. 対応 Locale

| code | name | native_name | 用途 |
|---|---|---|---|
| `en` | English | English | **default / fallback** |
| `ny` | Chichewa | Chichewa | |
| `ja` | Japanese | 日本語 | |

* Locale コードは BCP-47（ISO 639-1 優先）。将来例: `tum`（Tumbuka）, `sw`, `zh-Hans`, `fr`, `pt`。
* 有効言語は DB の `languages` テーブルで管理（`is_active`, `is_default`, `sort_order`, `direction`）。
  Backend はこれを 1 時間キャッシュして「サポート Locale 一覧」とする。
* **注意**: 同梱している Chichewa 訳は開発チームによる初版であり、リリース前にネイティブ話者のレビューが必要。
  レビューは翻訳ファイル／管理画面の編集だけで反映でき、コード変更は不要。

---

## 2. Locale 決定と Fallback

### Backend（API リクエスト単位）— `SetLocale` middleware

```
1. 明示的な Accept-Language ヘッダ（q 値順に評価、"ja-JP" → "ja" に正規化）で有効言語に一致したもの
2. ログインユーザーの users.preferred_language
3. languages.is_default（= en）
```

* 決定した Locale は `App::setLocale()` に設定し、レスポンスヘッダ `Content-Language` と `meta.locale` で返す。
* Laravel の `fallback_locale` = `en`。翻訳キーが対象 Locale に無い場合は英語にフォールバック。

### DB 翻訳の Fallback

```
要求 Locale の翻訳 → en の翻訳 → 存在する任意の翻訳（最終手段, sort by id）
```
`HasTranslations::translation($locale)` に一元化。クエリは **要求 Locale と fallback Locale のみ** eager load する
（`withTranslations()` scope）ため、言語が増えてもレスポンスサイズ・クエリ量は増えない。

### アプリ（Flutter）

```
初回起動: 端末 Locale を取得 → サポート一覧に言語コードが一致すれば採用、無ければ en
          → 言語選択画面で確認（初期選択済み）
以後    : ローカル保存（SharedPreferences）した Locale を使用
変更    : Account > Language で即時反映（MaterialApp.locale を state で差し替え、再起動不要）
          + ログイン中なら PUT /api/account/language で users.preferred_language を同期
API     : すべてのリクエストに Accept-Language: <現在の Locale> を付与
```

## 3. 翻訳キー設計

### キー命名規約（全クライアント共通の「正規キー」）

`<feature>.<sub>[.<sub>]` の英小文字スネークケース。

| 例 | en | ja |
|---|---|---|
| `home.title` | Home | ホーム |
| `home.delivery_to` | Deliver to | お届け先 |
| `product.add_to_cart` | Add to cart | カートに追加 |
| `cart.checkout` | Checkout | レジに進む |
| `order.place_order` | Place Order | 注文する |
| `order.status.cooking` (COOKING) | Preparing | 調理中 |
| `driver.new_delivery` | New delivery | 新しい配達 |
| `payment.cash` | Cash on delivery | 代金引換 |

* **ステータス・エラーコードの翻訳キーはコードから機械的に導出**する:
  `order.status.<status_code 小文字>`（例 `COOKING` → `order.status.cooking`）、
  `error.<ERROR_CODE 小文字>`（例 `OTP_INVALID` → `error.otp_invalid`）。
  → 新しいステータスが増えても、翻訳を 1 行足すだけ。
* 未知のコードを受け取った場合はクライアントは `error.unknown` / `order.status.unknown` を表示（クラッシュさせない）。

### Flutter での表現（ARB）

Flutter の `gen-l10n` は ARB キーに `.` を使えないため、**正規キーの `.` を `_` に置換** したものを ARB キーとする。

```
正規キー  order.place_order  →  ARB キー  order_place_order  →  Dart  l10n.order_place_order
```

```
customer-app/lib/l10n/
├── app_en.arb   (テンプレート / 全キーを持つ)
├── app_ny.arb
└── app_ja.arb
```

`app_en.arb` 例:
```json
{
  "@@locale": "en",
  "order_place_order": "Place Order",
  "@order_place_order": { "description": "order.place_order – checkout primary button" },
  "cart_item_count": "{count, plural, =0{No items} =1{1 item} other{{count} items}}",
  "@cart_item_count": { "placeholders": { "count": { "type": "int" } } }
}
```

* 動的キー（ステータス等）は生成コードの `switch` を 1 箇所（`StatusLabels`）に閉じ込める。画面側には置かない。
* **Chichewa は Flutter の Material/Cupertino 組込みローカライズ非対応** → `FallbackMaterialLocalizationsDelegate`
  （非対応 Locale は英語の Material 文言を返す汎用デリゲート）を登録する。言語コード固有の分岐ではなく
  「組込み未対応なら en」という汎用ルール。
* **数値・日付・通貨フォーマット**も `intl` のロケールデータが無い言語がある（`ny`）。
  `FormattingLocale.resolve(locale)` が「intl がサポートしていればその Locale、無ければ `en`」を返す
  汎用関数を 1 箇所に置き、`NumberFormat.currency(locale: ..., name: 'MWK')` / `DateFormat.yMMMd(...)` に渡す。
* レイアウト: 固定幅テキスト禁止。`Flexible`/`Expanded` + `softWrap`、ボタンは `minHeight` のみ指定し高さ可変。
  CI で最長言語の擬似ロケール（全文字列 1.4 倍）での Golden テストを行う（PHASE 2）。

### Backend（Laravel）

```
backend/lang/            (Laravel 9+ の標準位置 = 旧 resources/lang)
├── en/
│   ├── errors.php        ErrorCode ごとの補助メッセージ   ('OTP_INVALID' => '...')
│   ├── sms.php           SMS 文面（短文）
│   ├── notifications.php Push/Email テンプレートの初期値（PHASE 5 で DB へ seed）
│   └── validation.php    Validation メッセージ
├── ny/ …（同構成）
└── ja/ …（同構成）
```

* API は「コード」を返し、クライアントが翻訳するのが原則。Backend で翻訳するのは
  **validation メッセージ、error.message（補助）、SMS / Push / Email** のみ。
* `tests/Unit/TranslationFilesTest` が **全有効言語の lang ファイルが en と同じキーを持つこと**を検証する
  （validation.php は Laravel の fallback に任せるため対象外）。

## 4. DB 翻訳方式

「本体テーブル（言語非依存の値）」＋「`*_translations` テーブル（Locale ごとの文字列）」。

```
products                  product_translations
- id                      - id
- organization_id         - product_id  ─┐ unique
- category_id             - locale      ─┘ (FK languages.code)
- price                   - name
- image_url               - description
- is_active
- preparation_minutes
```

対象（PHASE 1 で実装）:

| 本体 | 翻訳テーブル | 翻訳カラム |
|---|---|---|
| product_categories | product_category_translations | name |
| products | product_translations | name, description |
| product_option_groups | product_option_group_translations | name |
| product_options | product_option_translations | name |
| stores | store_translations | description, announcement |

対象（後続フェーズ）: notification_templates（P5）、お知らせ・バナー（P6）。
店舗名・FC 名・住所など固有名は翻訳しない。

### API での返し方

* 顧客向け API: 解決済みの単一言語で返す（軽量）。
  ```json
  { "id": 1, "name": "チキン弁当", "description": "…", "price": 350000, "currency": "MWK" }
  ```
* 管理 API: 全言語を返し、編集できるようにする。
  ```json
  { "id": 1, "price": 350000, "translations": { "en": { "name": "Chicken Bento", "description": "…" }, "ja": { … }, "ny": { … } } }
  ```
* 管理 API での保存は `translations` オブジェクトを受け取り、`TranslationService::sync()` が upsert。
  英語（default locale）の `name` は必須、他言語は任意（未入力は fallback 表示）。

## 5. 注文のスナップショット（PHASE 3）

`order_items.product_name_snapshot` は **注文時の Locale の名称** を保存し、`order_items.locale` に Locale を記録。
価格は必ずスナップショット。注文履歴は snapshot を表示（商品が後で改名・削除されても変わらない）。

## 6. Push Notification（PHASE 5）

* `notification_templates(code, channel)` + `notification_template_translations(locale, title, body)`（管理 API で編集）。
  コード: `ORDER_CONFIRMED`, `ORDER_COOKING`, `DRIVER_ASSIGNED`, `ORDER_ON_THE_WAY`, `DRIVER_ARRIVED`, `ORDER_DELIVERED`,
  `ORDER_CANCELLED`, `DELIVERY_FAILED`, `PAYMENT_RECEIVED`, `PAYMENT_FAILED`（顧客）, `DRIVER_NEW_DELIVERY`（配達員）。
* 同梱の既定文面は `lang/<locale>/notifications.php`（`CODE => [title, body]`）。Seeder が DB にコピーし、以後は管理者が DB を編集。
* 送信は `SendOrderNotifications` リスナー → `SendNotification` ジョブ（キュー, コミット後）→ `NotificationService`。
  端末は `device_tokens`（アプリがログイン後に `POST /devices`）。送信結果は `notification_logs`（code, channel, locale, status）。
* ドライバ: `PUSH_DRIVER=log`（開発。ログに出力）/ `fcm`（FCM HTTP v1, サービスアカウント JWT）。無効トークンは FCM の応答で自動削除。
* 送信時 Locale: `user.preferred_language` → en fallback（テンプレート単位）。
* 解決順: DB テンプレート(locale) → DB テンプレート(en) → `lang/<locale>/notifications.php` → `lang/en/...`。
* 本文はプレースホルダ置換（`:order_number`）。金額等は `NumberFormatter`（PHP intl）で Locale 別に整形し、
  intl が該当 Locale を持たない場合は en で整形（アプリと同じ汎用ルール）。
* FCM の `data` には必ず `code` と `order_id` を入れ、アプリがフォアグラウンド時は自前の ARB で再翻訳できるようにする。

## 7. SMS

* 文面は `lang/<locale>/sms.php`（キー: `otp`, `order_confirmed`, `order_on_the_way`, `driver_arrived`）または DB テンプレート（channel=SMS）。**短文前提**。
* 送信対象（重要通知のみ）: OTP, 注文受付, 配達開始, 配達員到着。それ以外は Push のみ（コスト対策）。
* 文字コード: GSM-7 なら 160 文字/通、日本語など UCS-2 は 70 文字/通。
  `SmsMessage` が符号化と通数を計算し、`config('bento.sms.max_segments')`（既定 2）を超える場合は
  **en の文面にフォールバック**してログに警告を残す（汎用ルール、言語固有分岐なし）。
* OTP は数字を文頭付近に置き、全言語で短く保つ。

## 8. Email

低優先度（領収書等）。Laravel Mailable + `->locale($user->preferred_language)`。

## 9. 商品翻訳の運用

* 管理画面の商品編集は言語タブ UI（有効言語を `languages` から動的生成 → 言語追加で自動的にタブが増える）。
* 翻訳未入力の言語は一覧に「未翻訳」バッジ（PHASE 6）。
* 顧客には fallback（英語）で表示されるため、翻訳が揃うまで販売停止にする必要はない。

## 10. 言語追加手順（例: Tumbuka `tum`）

1. **DB**: 管理画面 Languages で追加（または Seeder / SQL）
   `code=tum, name=Tumbuka, native_name=Chitumbuka, is_active=false`
2. **Backend**: `backend/lang/en` をコピーして `backend/lang/tum` を作り翻訳。
   `php artisan test --filter=TranslationFilesTest` でキー欠落を確認。
3. **Customer / Driver App**: `lib/l10n/app_en.arb` をコピーして `app_tum.arb` を作り翻訳 →
   `flutter gen-l10n` → 新バージョンをリリース（UI 文言はアプリ同梱のため）。
   Material 非対応言語でも `FallbackMaterialLocalizationsDelegate` により動作する。
4. **DB コンテンツ**: 管理画面で商品・カテゴリ・オプション・通知テンプレートの `tum` タブを入力。
5. アプリの新バージョン配布後に `is_active=true`。
   アプリは `GET /api/languages` とアプリ同梱の supportedLocales の **積集合** を言語選択肢として表示するため、
   古いアプリには未同梱の言語は表示されない（安全）。

> コード変更は不要。`if (lang == "tum")` は書かない。
